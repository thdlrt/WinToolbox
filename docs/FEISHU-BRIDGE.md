# 飞书监听

在「Codex 配置 → 飞书监听」管理。监听器随 WinToolbox 后端运行；工具箱主窗口关闭到托盘后继续监听，彻底退出后停止。需要重启电脑后自动监听时，在「设置 → 通用」开启工具箱开机启动。

配置包含飞书 App ID、机器人 open_id、默认确认回复、最终回复等待时间及多条匹配规则。每条规则可设置私聊或群聊、chat_id、发送者 open_id、是否必须 @机器人、消息关键词、接收的消息类型、目标本机 Codex 对话和任务提示词。私聊必须指定发送者，避免其他人通过机器人取得该对话的权限。按配置顺序匹配第一条规则。修改后点击「保存配置」即生效；「检查连接」验证飞书 CLI 和 Codex 桌面接口，不发送测试消息。

提示词支持 `{rule_name}`、`{chat_id}`、`{message_id}`、`{sender_id}`、`{acknowledgement}`。监听器会追加身份复核及回复原消息的要求。对应 Codex 对话沿用自身的权限和上下文；规则的提示词应明确说明可执行范围。消息去重状态保存在 `feishu-bridge.sqlite3`，配置在 `feishu-bridge.json`，均位于便携版 `data` 目录，未加入自动数据同步或普通配置备份。

工具箱使用本机已有的 `lark-cli` 认证和 Codex Desktop app tools。未配置或未安装时显示实际错误。默认不启用任何规则，也不会自动导入其他脚本的授权。迁移旧监听器时，先保存并检查新配置，停止旧计划任务，再开启新监听，避免重复确认和派发。

## 私聊与群聊 context 路由

使用飞书“回复”某条消息时，监听器读取原消息的回复关系，继续它的来源 Codex 对话；连续追问、回复思考中确认和最终答复都保留来源。哪个 Codex 对话在群里提问，群成员的答复就回到哪个对话，即使该问题挂在更早的讨论下，也优先采用提问消息本身的发送回执。私聊非回复的新消息使用匹配规则中的默认对话；群聊仅 @ 的新消息先检查待答提问。

群聊不点“回复”、只 @机器人时，优先接续针对该发送者的待答提问，再检查面向群成员的提问。只有一个来源对话时自动接续；多个问题来自同一对话也可继续。多个来源无法唯一确定时，列出原问题及其链接，请群成员直接回复对应问题，不抢选最近对话，也不误送默认。没有待答提问时才使用默认对话。

「待答提问追问窗口」默认 168 小时（7 天），可设 0–720；0 关闭仅 @ 接续提问。只识别本机器人明确发出的询问、确认或索要信息，排除思考中和常规通知、其他机器人、过期和已答复问题；来源必须由本机消息映射或成功发送回执核验。人的回答送达后先保留待答状态，机器人作出后续答复时移除原问题；新的追问另行接续。状态持久化并支持重启后从消息关系恢复。一次最多读取 1000 条窗口内群历史，未能完整覆盖时提示使用明确回复，不宣称没有待答提问。

群规则开启「新消息必须 @机器人」时，回复机器人问题或已处理消息无需再次 @。普通群成员之间的回复，没有机器人消息或已处理消息来源时安静忽略，不发送思考中确认。仍遵守配置中的会话、发送者、关键词和消息类型限制；群回复不会获得主人私聊权限。

升级前的群聊映射可能仅记录了默认对话，回复时先重新核验来源再更新映射；保留原有任务和私聊记录。

消息与 context 的对应关系保存于本地 SQLite，重启及修改默认对话后仍然有效。其他任务主动发来的通知，以及升级前的消息，会尝试从本机 Codex 执行历史中的成功飞书发送结果恢复来源。只接受同一会话内已核验的用户、本机器人消息和唯一发送记录；私聊额外限定主人身份。不会根据消息正文里的对话 ID 或链接选择 context。缺失本机历史、没有成功发送回执、来源冲突或回复链无法核实时，显示失败原因，不进入默认对话。远程设备及未保留发送记录的通知暂不支持自动恢复。

“最近处理”展示实际派发的 context ID。来源恢复只读本机 Codex 历史，不修改 Codex 数据库；缓存不参与云端同步。
