# 项目记忆

项目 → 设备（Windows 工具箱或独立 SSH 记录端）→ 全局 WebDAV。界面和中央数据由 WinToolbox 管理，无需启动 Obsidian。

## 数据与身份

- `data/project-memory/memory.sqlite3` 保存项目、任务、知识与不可变版本日志；附件位于 `blobs/<sha256>`。SQLite 在线备份纳入工具箱快照。
- `library_id` 标识同一个全局库，`project_id` 标识逻辑项目，设备 ID 与写入副本 ID 独立。复制便携版数据到另一电脑不会复制操作身份。
- 设备 ID 位于 `%LOCALAPPDATA%/WinToolbox/agent/device-id`，Linux 为 `${XDG_STATE_HOME:-~/.local/state}/wintoolbox-agent/device-id`；它不在便携数据和 WebDAV 内。
- 本机与 SSH 目录按设备登记。项目 `.agent/toolbox.json` 或已有 `.agents/toolbox.json` 只含库和项目身份。项目目录在某台电脑不存在时，仍可浏览同步内容，不能打开或修改别处的目录。移动目录时重新关联同一项目 ID。
- 每台设备分别订阅项目。同步先下载项目目录信息与全局知识，只下载已订阅项目正文；取消订阅停止后续下载，保留已有离线副本。
- `scope=project/global` 是知识适用范围，不等于存储位置。项目知识上传服务器仍为项目知识；全局记忆由同一库的设备共享。

## 同步

复用设置中的 WebDAV 加密凭据，独立使用 `<工具箱远端目录>/project-memory/<库ID的SHA256>/`。原 `.wtbak` 快照不改变。

服务器保存 `library.json`、`catalog/`、`global/`、`projects/<项目ID哈希>/`、`blobs/`。记录以不可变操作 ID 哈希命名，附件先传、正文后传；创建使用 `If-None-Match: *`。日常按目录增量传输，`memory.sync.run {"verify":true}` 可完整核验已有不可变内容。服务器端不执行 AI、不管理本机路径、不接收 SSH 私钥。

新设备选择“查找已有记忆库”，在空库中加入同一 ID，然后同步和选择项目订阅。非空异库不自动混合。即使电脑没有任何项目目录，也可订阅和阅读知识；绑定本机目录是独立动作。

已保存 SSH 目标先逐台交换，再同步 WebDAV；远端离线不阻断其他目标与 WebDAV，警告保留在同步结果。自动同步在工具箱运行期间每 5 分钟尝试，离线修改一直保留；退出工具箱后远程 CLI 仍可独立记录，下次连接再同步。

相同记录离线同时修改会保留多个版本。界面选择版本或编辑合并后，以所有当前 heads 为父版本发布。时间戳只作显示，不用来决定谁覆盖谁。重试幂等，丢失父版本保持待接收，附件未落盘不确认完成。

## SSH

仅连接用户明确保存的 SSH 主机别名或 `user@host`，使用系统 OpenSSH、已验证的主机密钥和现有认证。远端需 Python 3.10+；无需安装第三方 Python 包或常驻服务。

“安装远程记录工具”在指定专用目录安装 `runtime/`，记录保存在 `data/`。客户端登记在远端用户状态目录 `client.json`；已登记不同目录时拒绝覆盖。同步时可同时指定项目 ID 和远端现存项目目录完成身份绑定，不会创建项目源代码目录。

```sh
PYTHONPATH=/home/user/.local/share/wintoolbox-agent/runtime \
python3 -m toolbox.project_memory --store /home/user/.local/share/wintoolbox-agent/data \
recall --project /home/user/project --query 配置
```

个人 agent-knowledge 技能读取 `client.json`，Windows/WSL 可共同调用便携版的 Windows Python，避免产生两个 PC 记忆库。远端可用相同技能，或直接调用上述 CLI。凭据只留在 PC，服务器通过 SSH stdio 交换完整性校验后的记录。

## 记录与 AI 整理

任务完成（done）即归档；“已完成”筛选可查看。知识保留分类，没有进度状态。项目卡片分别过滤全部、知识、任务。

项目知识提升后生成带源版本的全局候选，原项目知识保留。用户已授权 AI 自行审批。工具箱使用当前配置的模型进行整理；本地模型模式没有云端回退。指定一台设备自动处理新候选，执行设备策略作为全局记录同步；策略冲突时暂停自动整理。无法核实的结论保持候选，模型错误不产生假审批；决定、理由、源版本和设备保留在记录版本中。CLI 的 curate 支持当前 AI 直接作出有理由的接受或拒绝。

## 基本原则

项目记忆页面的“基本原则”可以编辑个人全局 `CODEX_HOME/AGENTS.md` 中的 agent-knowledge 管理区块，区块外内容保留，保存校验读取时的文件版本。它仍是 Codex 原生全局指令；工具箱不声称当前已经运行的会话会热加载新规则。

“新项目模板”作为全局内部记录同步，只在未来首次关联/初始化项目时追加管理区块，已有项目区块不自动覆盖。模板与个人全局规则分开维护，避免每次改动复制到所有项目。

若项目同时已有 `.agent` 和 `.agents`，关联时明确选择原有知识连接目录，或 CLI `init --context-dir .agent`。不自动删除或合并另一目录。

远端安装也提供不依赖 Node 或 Codex 技能的入口：

```sh
python3 "${XDG_STATE_HOME:-$HOME/.local/state}/wintoolbox-agent/agent-knowledge.py" recall --project .
```

SSH 首次绑定项目时会把这个入口写入新建的项目原则区块；已有自定义区块保留。安装过程不会修改远端 Codex 技能目录。

## 日常使用

| 位置 | 放什么 | 是否同步到其他设备 |
| --- | --- | --- |
| 项目 | 某个项目的任务、经验和配置 | 订阅该项目的设备可接收 |
| 全局知识 | 跨项目通用经验、个人偏好 | 同一记忆库的设备共享 |

“本地”不代表未上传：所有内容都有本地离线副本，适用范围决定是否同步。

页面默认打开任务看板。按项目范围、状态、最近更新时间及关键词筛选，点击任务即可编辑。默认显示未完成；切到已完成或全部状态查看历史。看板范围是本机已经同步到的内容，未订阅项目可能尚未下载完整任务；项目没有本机目录不影响查看。

当前电脑已经配置 WebDAV，保持自动同步即可。另一台电脑在工具箱设置中配置同一个 WebDAV，再打开“同步设置 → 其他电脑 → 另一台电脑怎么接入？”，查找并加入原记忆库，然后订阅需要的项目；有代码目录时再关联本机路径。

只有服务器上的 Codex 需要独立记录时才配置“SSH 服务器”：填写可连接的主机别名、服务器专用记录目录，选择项目及其远端代码目录，依次安装记录工具、双向同步、保存连接。同一服务器只需安装一次。PC 关机后远端仍可本地记录，PC 恢复连接后交换到工具箱，再通过 WebDAV 分发给其他电脑。WebDAV 本身不运行 AI，也不会自动连接 SSH。

不再显示最近操作列表。手动操作的进行状态、失败原因仍会显示；导出完成后可直接打开文件。

记忆仅保留项目与全局两个作用域。“仅本机”层级已取消，旧 device 记录在打开数据库时备份并转换为 global，保留 ID、正文、附件和完整版本关系，随后参与同步；不转换设备路径、订阅或凭据。其他设备需更新记录工具后应用此变更。
