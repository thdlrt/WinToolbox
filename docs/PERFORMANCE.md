# 后台内存优化（2026-09-29）

## 改动

- 常驻 Python 入口在导入音频依赖前默认设置 `OPENBLAS_NUM_THREADS=1`。小音频缓冲区不需要按 CPU 核数分配 BLAS 线程与工作区；显式环境变量仍优先。没有修改用户或系统环境变量。
- 主窗口与悬浮球分开加载；工具页面通过 React.lazy 按需加载，Markdown 等较大的依赖只在相关页面需要时加载。加载提示保留在内容区，侧栏保持可用。
- `visiblePolling` 统一管理普通状态刷新：隐藏/最小化时停止定时请求，恢复后立即刷新，同一轮询最多一个请求在途。覆盖任务列表、同步指示器、悬浮球状态、内存页、FN 状态、账本同步及字幕状态快照。
- 任务事件仍实时更新可见界面；任务列表的兜底轮询从 4 秒改为 15 秒。正在执行的文件操作、悬浮球上传队列及其完成处理不随窗口隐藏而取消。
- 原生窗口管理每 2 秒检查可见性，只在状态变化时切换 WebView2 的低/正常内存目标。托盘打开主窗口时立即恢复正常目标。使用低内存目标而非暂停 JavaScript，以保留后台播放、录音相关控制和任务完成处理。

WebView2 能回收的内存由其运行时决定；页面、表单和播放状态保留，没有通过销毁窗口或清空系统工作集制造短期读数下降。接口依据：[Microsoft ICoreWebView2_19](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_19)。

## 本机测量

单位 MiB。**工作集是驻留物理内存，私有提交量包含可能换出的内存；二者不能混用。**进程树工作集简单求和可能重复计入共享页。

| 场景 | 工作集 | 私有提交量 |
| --- | ---: | ---: |
| 独立 Python，仅导入 NumPy，原默认线程池 | 25.7 | 755.1 |
| 相同 Python，单线程 OpenBLAS | 24.4 | 16.1 |
| 原实际会话整个进程树 | 849.29 | 1313.44 |
| 新版实际会话，打开实时助手后 | 725.86 | 473.06 |
| 新版最小化，保留悬浮球与已启用服务 | 668.29 | 467.82 |
| 新版关闭主窗口至后台，保留悬浮球 | 661.88 | 473.46 |

实际会话的 Python 后端私有提交量由约 797 MiB 降至约 52 MiB。整机环境、窗口访问历史和后台服务状态会影响进程树读数，实际会话数据是运行快照，不能视为严格相同负载下的 A/B 基准；独立 NumPy 对照确认了主要提交内存来源。

`scripts/measure-memory.ps1` 可重复采样当前 WinToolbox 及其子进程，不修改应用状态：

```powershell
scripts/measure-memory.ps1 -Label background -OutputPath .build/background-memory.json
```

本次原始记录在 `.build/performance/*.json`，不包含命令行、设置或凭据。

## 后续约束

- 不为了空闲省内存退出承载同步、热键、上传或实时音频的 Python 后端。
- 新增普通状态轮询应使用 `visiblePolling`；会推进任务流程的轮询需单独评估，不能直接停止。
- 新增较大页面或依赖应保留动态导入边界，避免悬浮球重新引入主界面代码。
