# Backend and desktop contract v1

Transport: newline JSON-RPC 2.0 stdin requests {jsonrpc,id,method,params}; stdout result/error. Notifications {jsonrpc:"2.0",method:"event",params:{type,...}}. Rust command rpc(method: string, params: object) -> result. Rust forwards notifications as Tauri event `backend-event`. Rust native commands: pick_files(multiple,filters?), pick_directory(), open_path(path), set_overlay(visible), app_paths(). Frontend src/api.ts wraps these; browser preview must show backend unavailable, not fake results. Overlay route `?overlay=1` shares backend.

Python conventions: feature modules expose `register(app)` and call `app.register(name, handler)`; handler gets params dict, returns JSON-compatible result. app.data_dir: pathlib.Path; app.emit(type, **fields); app.jobs.submit(tool,params,runner)-> job dict, where runner(job) and job.progress(percent,message), job.check_cancelled(), job.artifact(path,kind,label), job.id. app.settings.get()->dict; app.settings.update(dict)->dict. app.providers.chat(messages, role='chat', stream_callback=None)->str; app.providers.embed(texts)->list[list[float]]. `app.jobs` created before registering features. Feature package register_all(app) loads its modules. Secrets are never returned by settings.get; use app.settings.secret(provider_id) for provider secrets.

Settings shape: {providers:[{id,name,kind:'openai'|'dashscope'|'gemini',base_url,api_key?,model?,region?}],roles:{transcribe:{provider_id,model},live_asr:{provider_id,model},translate:{provider_id,model},chat:{provider_id,model},vision:{provider_id,model},embedding:{provider_id,model},tts:{provider_id,model}},preferences:{library_path?,theme?,record_audio:true},presets:[]}. API key sent only on update; get returns has_key boolean. Roles defaults use DashScope model presets, no credentials. Backend data path passed via --data-dir.

Package manifest {id,name,version,api_version:1,description,entrypoint,runtime:'python',permissions:[],ui?:{fields:[]}}. Support declarative fields and JSON output in v1, include working file-hash sample.

No fake success on unavailable external dependencies/keys. Provider streaming, cancellation and errors must be surfaced. Methods absent during integration return structured method-not-found. Engine imports features.register_all after infrastructure; root wires live.register(app).

Model profiles (0.1.2): preferences.model_mode/local_preset/asr_engine/asr_model/asr_device/asr_compute_type control new media/live operations at both UI and backend boundaries. Local mode routes chat/translation/vision/embeddings to the private LocalLLM runtime; it blocks cloud overrides and cloud ASR/TTS. LocalASR is faster-whisper; local dubbing uses the separately installed CosyVoice. Old settings without model_mode retain advanced/manual routing. The private Ollama process uses loopback, separate home/model directories and disabled cloud capability. Model download is an explicit install task. Models are under models/ollama and the runtime under runtimes/ollama, covered by include_models backup; single-model runtime-package export/import is not supported for shared Ollama blobs.

Captions (0.1.3): captions.state/start/stop/configure -> {active,session_id,status,message,segments,options,revision}; start/configure accept options {system_id,display_mode:'bilingual'|'translation'|'original',font_size:16..64,background_opacity:0..1,target_language,click_through}. Configuration persists under preferences.captions. Captions force system capture, no microphone/recording/history/Q&A, share the live holder to prevent simultaneous meetings, and follow current model mode. Events captions.segment/status/config include monotonically increasing revision; segments include id/session_id/seq/text/translation/final/source/start/end. Retain at most 30 recent segments and bounded translation work. Original mode never invokes translation. Late translation patches the same id; stopped/replaced sessions reject old results.

Native caption commands: set_captions_window {visible}, set_captions_click_through {enabled}, get_captions_window -> {visible,click_through,recovery_shortcut_available}; native events use backend-event type='captions.window'. Showing unlocks the window, hiding does not stop capture. Explicit UI close first calls captions.stop; OS close is intercepted and stops asynchronously. Caption window route ?captions=1 is transparent, borderless, always-on-top, not focusable, and off the taskbar. Ctrl+Alt+L shows/unlocks; Ctrl+Alt+C toggles visibility. Tray actions provide independent recovery and stopping.

Local API usage accounting (0.1.6): `engine.sqlite3.api_usage` stores counters only: provider/model/role/operation/status, response-reported tokens, sent audio seconds and latency. It never stores prompts, responses or credentials. Chat streaming requests use DashScope `stream_options.include_usage`; file/realtime ASR records known audio duration. Statistics begin after this schema is installed and are not Alibaba Cloud account billing, balance or historical backfill.

Oral practice (0.1.7): practice.generate {text,voice?}->job (result is item); practice.list {}->{items:[]}; practice.get {id}->item {id,text,voice,model,created_at,sentences:[{text,audio_id,duration}],path}; practice.audio {id:audio_id}->{data:base64,mime:'audio/wav'}; practice.word {word}->{word,ipa:[],source,label,note}. Sentences are normalized WAVs and content-addressed by text/provider endpoint/model/voice. Existing audio is verified before reuse; concurrent duplicates share a generation lock. Complete WAV and relative sentence IDs persist under data/practice and travel in backups. Local mode can replay cached audio but generation requires an API TTS provider. Playback rate and loop never trigger generation. Pronunciation is offline CMUdict converted to US IPA; unavailable words are explicit.

Live assistant document libraries (no standalone Q&A page): knowledge.list {}->{collections:[]}; knowledge.create {name,prompt?}->{id,name,prompt}; knowledge.documents {collection_id}->{documents:[]}; knowledge.ingest {collection_id,paths,visual?}->job (extract and persist embeddings in advance); knowledge.search {collection_id,query}->{results:[]}; knowledge.delete {collection_id,document_id?}->{ok}. Existing knowledge.ask remains an internal compatibility API.

Library preparation (0.1.5): knowledge.index_status {collection_id}->{status:'empty'|'indexing'|'ready'|'keyword-only'|'needs-index',ready,document_count,chunk_count,indexed_chunk_count,embedding_model,message,warnings,job_id?,progress?}. Status inspection never calls a model. knowledge.reindex {collection_id}->job embeds only missing/stale saved chunks, without parsing source files again. Index vectors persist in the library SQLite database. Live library selection is fixed for the active session; both automatic and manual answers retrieve from that selected library.

Paragraph practice (0.1.8): practice.save {id?,text?,voice?,folder_id?,revision?}->item saves without synthesis; practice.move {id,folder_id,revision?}->item. Stable paragraph IDs own fragments and audio versions. practice.generate {id,text?,voice?,force?,revision?}->job; practice.fragment {id:parent_id,text,fragment_id?,force?,revision?}->job returns a child fragment. Ordinary generation reuses the latest matching audio, including forced versions. Text/voice edits advance content_revision and mark audio stale; folder changes advance revision only. Obsolete jobs cannot overwrite or revive edited/deleted records. practice.delete {id,fragment_id?,revision?}->{ok,archive_path} archives records, retaining shared audio. practice.folders.list {}->{folders:[]}; practice.folders.create {name}, practice.folders.rename {id,name}, practice.folders.delete {id} (moves paragraphs to unclassified). practice.voices {}->{model,source,source_url,checked_at,custom_allowed,voices:[{id,name,description}],notice} is a versioned official system-voice catalogue filtered by exact model, not an account clone enumeration API. Unknown models allow custom IDs without guessing compatibility. Legacy paragraph IDs/audio remain readable.

WebDAV snapshots (0.1.9): webdav.get {} -> {url,remote_path,username,has_password,configured,include_media,include_models,include_secrets}; webdav.save {url,remote_path,username,password?,clear_password?,include_*?} stores DPAPI credentials in excluded webdav.json, empty password keeps the saved value except when endpoint/user changes. webdav.test {} -> {ok,message,remote_path} checks PROPFIND and may create only the final directory. webdav.list {} -> {snapshots:[{name,size,modified_at,encrypted}],remote_path}. webdav.upload {include_media?,include_models?,include_secrets?,backup_password?}->job; webdav.restore {name,backup_password?}->job with recovery_path/restart_recommended result. Credentials remain in memory; job params contain only an opaque token and nonsecret options/name. Immutable UUID snapshots publish by temporary PUT then MOVE Overwrite:F; redirects are rejected and default ports normalized. Restore validates before generating a persistent local recovery snapshot and replacing managed data under the app data gate. No automatic two-way merge. Backup directories now explicitly represent empty managed roots; omitted optional model roots remain outside scope. Late cancellation after committed replacement/publication does not falsely report cancelled.

Monthly expenses (0.1.10): expenses.list {month?:'YYYY-MM'} -> {month,items,summary:[{currency,count,total,pending,reimbursed,...,*_minor}]}; summary money is exact two-decimal strings, with integer minor-unit fields; currencies are never combined. expenses.save {id?,revision?,title,date:'YYYY-MM-DD',amount:string,currency?:'CNY'|'USD'|'EUR'|'HKD',status?:'unsubmitted'|'submitted'|'reimbursed'|'personal',category?,notes?}->entry; expenses.get {id}->entry; expenses.delete {id,revision?}->{ok,archive_path}. IDs are 32 lowercase hex; revisions reject stale edits. expenses.attach {id,revision?,paths:[],kind:'invoice'|'receipt'|'payment'|'other'}->job with {id,entry,attachments} result; batches copy source files into owned paths without changing originals, validate signatures and size, and publish metadata only after all copies succeed. expenses.attachment {id,attachment_id}->{path,name,kind,mime}; expenses.attachment.delete {id,revision?,attachment_id}->{ok,entry,archive_path}. Attachments store original_name, kind, size, sha256 and relative_path, support PDF/PNG/JPEG/WEBP/OFD, 50 MiB/file and 200 MiB/batch. Deleted records are archived; attachment files remain recoverable. expenses is a managed backup root, including receipt images even when include_media=false. Old snapshots without expenses scope preserve current bookkeeping data. There is no automatic recurring charge or exchange-rate conversion.

Caption stability (0.1.11): source_language auto/en/zh/ja/ko/fr/de/es persists in caption options and maps to cloud language_hints, Qwen realtime input_audio_transcription.language, and local Whisper language; running capture rejects changes to source_language. The display receives immutable final:true cues from stable prefix assembly, including utterance_id/page_index/recognition_final/duration_ms and translation_state pending|ready|failed|disabled. Raw revisable partials stay inside the assembler; a later service final adds only the remaining tail. Semantic ASR segmentation is enabled for the current Bailian streaming model. Frontend pairs source/translation by cue ID, waits up to 3 seconds for translation, then freezes that cue's display; all text pages remain readable, with bounded queued reading time and a catch-up notice. No cross-cue latest translation or tail clipping.

The global task-center page is removed. Job RPC/storage remain internal execution infrastructure. ToolJobs scopes progress/cancellation/retry/artifacts to each relevant tool; Practice, Expenses and WebDAV use their own local progress and cancel controls. Expense periods and income (0.1.12): entries add entry_type expense|income (missing defaults to expense). Expense statuses are waiting/reimbursed/non_reimbursable; reads normalize legacy unsubmitted/submitted to waiting and personal to non_reimbursable without rewriting files. Income uses not_applicable, positive amount, owned attachments as before. expenses.list accepts either month or start_month+end_month inclusive, plus query/entry_type/status/category/currency filters. Returns start_month/end_month, items after filters, categories from the entire period, summary_scope='period', and independent per-currency whole-period summary {expense_total,reimbursed,pending,non_reimbursable,transfer_income,net,...} with exact decimal strings and *_minor integers. net=transfer_income+reimbursed-expense_total; old total aliases expense_total. Counts remain integers. Summary is not recomputed from filtered items. Reimbursement grouping uses the expense record date, not a separate payout date. Income↔expense edits preserve IDs/attachments and normalize reimbursement status. No cross-currency conversion.

Shared-cost settlement (0.1.13): expenses.list additionally returns share_due and settlement_remaining (decimal strings plus *_minor integers) per currency. share_due_minor=(expense_total_minor-reimbursed_minor+1)//2: subtract only reimbursed costs, then halve the entire inclusive period total and round half a cent up once. Do not round per record or month; waiting and non_reimbursable expenses remain in the shared cost. settlement_remaining_minor=share_due_minor-transfer_income_minor. UI labels positive as 还需转入, negative as 多转金额 with its absolute value, and zero as 已结清. The previous net field remains for compatibility but is no longer the primary UI comparison. Filters, data schema, record revisions and attachments are unchanged; restore recomputes derived totals from restored records.

Shizuku (0.1.15): shizuku.status reports adb_available/adb_path/last_target. shizuku.discover/start/pair return background jobs; discovery lists TLS mDNS services and attached wireless devices, without network port scans. start accepts target as a private IPv4:port, connects, validates get-state and package availability, starts the fixed official script, then checks pidof shizuku_server. pair accepts pair_target, six-digit code, and optional same-IP/different-port target; if omitted, only a unique same-IP TLS connect service may be selected. Results distinguish paired from running; only running=true means service confirmed at task completion. Pairing secrets travel via stdin and ephemeral memory, never persistent job params/logs; generic jobs.submit rejects code/pairing_code/password for this tool. Pair retry requires a new code. Existing Android ADB server and local credentials are used, never kill-server or adb tcpip; cancellation stops only this client. settings.preferences.shizuku_target remembers the last connected address; Android host credentials are not synced. Official ADB 37.0.1 and notices are staged by scripts/prepare_adb.py to tools/adb with fixed archive SHA-256.


FN Connect (0.1.16): fnconnect.status returns {state,tun}; fnconnect.connect {origin,username,password,scope:lan|all} returns a background job. Credential material stays only in memory; job params contain an expiring one-use credential_token, origin and scope. Dedicated disconnect/probe/tun-start/tun-stop methods return jobs. SOCKS5 listens only on 127.0.0.1:18792 and supports TCP CONNECT. The NAS policy supplies permitted LAN networks and public-egress permission. TUN uses bundled Mihomo 1.19.30, prompts for administrator elevation, and stops when its runtime lease expires. No UDP/IPv6 tunneling in this experimental version; global mode rejects those protocols. NAS session restoration uses a refreshed WebSocket cookie handshake before user.tokenLogin. Main-window close hides to tray; tray Quit ends the backend and TUN.

### FN Connect remembered login (0.1.18)
`fnconnect.profile` returns origin, username, scope and remember (never the password). `fnconnect.connect` accepts remember; an empty password reuses saved credentials only for the exact normalized origin and username. Successful login saves DPAPI current-user ciphertext to fnconnect-login.json. `fnconnect.forget` removes it. Sessions remain memory-only.

### TUN service and remembered toggle (0.1.19)
TUN status adds `enabled` (persisted preference), `service` and `available`. Successful FN Connect login restores an enabled TUN. Manual `fnconnect.tun-stop` clears the preference; connection failure, reset, disconnect and application exit stop routing without changing it.
The first TUN start installs WinToolboxTun with one UAC prompt. A fixed C# LocalSystem service and pinned Mihomo live in an administrator-writable Program Files directory. Owner-SID-restricted local named-pipe RPC accepts only start/status/stop/heartbeat with structured target inputs, never raw Mihomo config, commands or executable paths. Routes are removed after 15 seconds without a lease or if the service exits (job-object process guard). Daily toggles and reconnects do not elevate the desktop app. Service installation or repair still needs UAC.
To remove the helper, run elevated PowerShell: `Stop-Service WinToolboxTun; sc.exe delete WinToolboxTun`. This unregisters the service and stops its routes; installed files may remain.
