# Backend and desktop contract v1

`ai_proxy.models.refresh {}` → background job returning current proxy status with full namespaced `models`, `models_refreshed_at`, and `model_errors`. Concurrent refresh clicks reuse one active job. Model discovery only calls upstream GET models endpoints; cache persists locally and errors preserve prior entries. Reading `ai_proxy.status` does not query upstreams. HTTP `/v1/models` shares this catalogue with a 5-minute cache.

AI local gateway: `ai_proxy.status {}` → `{running,enabled,port,base_url,protocol,models,keys,error}`; `ai_proxy.configure {enabled?,port?}` restarts the loopback listener. `ai_proxy.keys.create {name?}` → `{id,name,api_key,base_url}` returns the application key once; `ai_proxy.keys.revoke {id}` invalidates new requests. Only SHA-256 digests are stored; no plaintext key in status or jobs. HTTP Bearer-authenticated `GET /v1/models` and `POST /v1/chat/completions` (stream/nonstream/tools) use namespaced model IDs and per-account upstream credentials. Default `127.0.0.1:18791`; other API protocols return 404. See [AI aggregation](AI-QUOTA.md).

AI development calls: `ai_calls.list {}` → `{routes:[{id,name,provider,base_url,default_model,enabled,ready,error,sources,usage}]}`; `ai_calls.save {account_id,model?,enabled?,source_provider_id?,api_key?}` saves a DPAPI-protected call key without changing quota cookies; no credential is returned. `ai_calls.models {account_id}` → job returning `{account_id,models:[{id}]}`. `ai_calls.submit {request_id,project?,concurrency?:1..6,tasks:[{account_id,model?,prompt?|messages?,tools?,max_tokens?:32..32768,timeout?:5..600,label?}]}` → idempotent job. Result `{request_id,successful,failed,results:[]}` preserves per-item errors/partial text, raw usage and nullable metrics. Batch completion is independent of model success. `ai_calls.get {request_id}` retrieves job and ordered results. RPC/CLI use the existing authenticated loopback transport, no extra public server; no implicit fallback/retry. See [AI quota and calls](AI-QUOTA.md).

QQ bridge: `qq.bridge.status {}` returns `{config:{enabled,thread_id,groups,launch_codex},bound,app_id,owner_id,connected,binding,last_error,qr_path,qr_url,pair_code,pair_expires_at,last_event_at,recent}`; secret fields and reply tokens are omitted. `save {config}` validates the selected local Codex thread and exact group allowlist; `bind {}` begins official QR pairing in a resident worker; `cancel {}` cancels it; `pair {}` rotates a local, 15-minute code only for an unpaired bot. `message {reply_token}` reads the stored source. `reply {reply_token,request_id,text?,files?}` sends to that fixed source, returns `{ok:true,message_ids:[...]}` only after QQ acknowledgement, and rejects an id reused for different content. `receipt {request_id}` returns `{status,result?}` with sending/sent/unknown/not_found. Unknown send outcomes are never automatically resent. See [QQ bridge](QQ-BRIDGE.md) for owner checks, lifecycle and platform limits.

Local CLI (2026-10-25): `python -m toolbox.cli` or portable `wintoolbox.cmd` connects to the resident backend over authenticated loopback JSON-RPC. `cli.methods {prefix?}` lists registered backend methods, excluding native `app.prepare_exit`. `data/cli-runtime.json` contains a random loopback port and current-user DPAPI credential, rotates each launch and stays outside managed backups/sync. See [CLI.md](CLI.md).

GPU guard (local development): `gpu_guard.status` returns session enabled/active state, local apps, pending_restore count, power, last sample, errors and software_rendering flag. `gpu_guard.apps {path,remove?}` edits existing .exe paths only while disabled and fully restored. `gpu_guard.enable {enabled:bool}` applies reversible per-user power-saving preferences on battery, restores on AC/unknown power, stop and exit; no firmware/device disabling or process termination. `gpu_guard.rendering {enabled:bool}` changes a per-user, per-toolbox software-rendering startup flag; restart required. `gpu_guard.scan {}` and `gpu_guard.power {}` return background jobs: scan uses OS counters, power explicitly invokes nvidia-smi once and may wake the dGPU. `gpu_guard.activity` emits a rate-limited in-app message. ### FN Connect remembered login (0.1.18)
`fnconnect.profile` returns origin, username, scope and remember (never the password). `fnconnect.connect` accepts remember; an empty password reuses saved credentials only for the exact normalized origin and username. Successful login saves DPAPI current-user ciphertext to fnconnect-login.json. `fnconnect.forget` removes it. Sessions remain memory-only.

### TUN service and remembered toggle (0.1.19)
TUN status adds `enabled` (persisted preference), `service` and `available`. Successful FN Connect login restores an enabled TUN. Manual `fnconnect.tun-stop` clears the preference; connection failure, reset, disconnect and application exit stop routing without changing it.
The first TUN start installs WinToolboxTun with one UAC prompt. A fixed C# LocalSystem service and pinned Mihomo live in an administrator-writable Program Files directory. Owner-SID-restricted local named-pipe RPC accepts only start/status/stop/heartbeat with structured target inputs, never raw Mihomo config, commands or executable paths. Routes are removed after 15 seconds without a lease or if the service exits (job-object process guard). Daily toggles and reconnects do not elevate the desktop app. Service installation or repair still needs UAC.

### Selective FN API port mapping (0.1.21)
`fnconnect.forward.list`, `fnconnect.forward.save`, `fnconnect.forward.enable` and `fnconnect.forward.delete` manage up to 24 persisted rules under `data/fnconnect/forwards.json`; the directory participates in backup and WebDAV snapshots. A rule maps a fixed `127.0.0.1:local_port` to one literal LAN IPv4 and TCP port through the authenticated FN tunnel. Enabled rules wait while disconnected and restart after login. Mappings always request `scope:'lan'`, even when the main connection uses global scope; the target must match the validated networks returned by the NAS bridge, and missing/invalid policy fails closed. Hostnames, public/loopback/link-local/multicast targets, LAN listeners, UDP, IPv6 and reserved local ports are rejected. Each listener admits at most 16 concurrent connections. Disabling, deleting, disconnecting, reset and application exit close the listener and its active local/WS sockets. Rules contain no FN credentials or forwarded payloads.
To remove the helper, run elevated PowerShell: `Stop-Service WinToolboxTun; sc.exe delete WinToolboxTun`. This unregisters the service and stops its routes; installed files may remain.

# FileSync local synchronization

`filesync.status` returns rules (without internal baselines), recent history and discovered legacy config/log paths. `filesync.save` accepts `id?`, `name`, `kind: file|folder`, `source`, `target`, `bidirectional`, `auto`, `deletes`, `interval` (5–86400 seconds), `retention` (0–3650 days), `include[]`, `exclude[]`; structural edits reset the baseline. `filesync.remove {id}` removes only the rule.

`filesync.preview {id}`, `filesync.sync {id, token, resolutions?}`, and `filesync.import {path}` return ordinary jobs. Preview results contain `token`, `operations[{path,action,reason}]`, `changes`. Sync revalidates the token against the current rule and file content; conflict resolutions map relative paths (empty string for a single file) to `source|target`. Import accepts old JSON or JSONL logs, returns `imported`, per-rule `errors`, `recovered`, and never enables automatic sync. Internal polling submits `filesync.sync` with `automatic: true` and never resolves conflicts automatically.

Rules/baselines/history use `filesync_rules` / `filesync_history` tables in the existing versioned engine SQLite database; no changes to the engine schema version are required for these additive tables. App restore initializes missing tables and disables automatic rules. App shutdown stops new poll jobs. All external writes run through background jobs and an execution gate; edits fail fast while a job owns the gate.
# File relay (WebDAV inbox)


`relay.get/save` read/write the local connection (`url`, `username`, `remote_path`, `download_dir`, write-only `password`). DPAPI ciphertext stays in `relay-connection.json`, excluded from ordinary backups and job records. Changing URL/account clears the old password; all saves rotate a configuration revision.

`relay.test`, `relay.list {path}`, `relay.mkdir {path}`, `relay.upload {paths,path?,move?}`, `relay.download {paths}`, `relay.cleanup_preview {days}`, `relay.cleanup {token}` are background jobs. Paths inside the remote inbox are relative, slash-separated and traversal-checked. Upload is PUT-to-temporary then MOVE with Overwrite:F; move-local mode additionally downloads and hashes before removing a verified unchanged local file. Downloads publish without replacing existing local files. Upload returns uploaded/moved/error arrays for partial outcomes.

Cleanup previews recursively enumerate files only; strong ETags and timestamps are required. Tokens are in-memory, revision-bound, single-use, valid for ten minutes. Execution rechecks metadata and uses conditional DELETE per file, retaining directories and concurrently modified files.

`relay.context_menu {enabled?}` controls only HKCU WinToolboxRelay file/directory verbs. Native `--relay-upload <absolute paths...>` is handled on initial launch and by the single-instance callback, forwarded to `relay.enqueue {paths}` with copy-only semantics to the inbox root. `relay.open` emits navigation; `relay.pending` consumes the most recent cold-start request so a frontend that subscribes later still opens the correct page. `relay.*` jobs reject credential-shaped parameters; dedicated submission allowlists persisted fields.

`quick.run {id,action:'clipboard_ocr'}` 为默认始终显示的内置动作，点击时记录 Windows 剪贴板序列号，后台读取 PNG/DIB/DIBV5 图片，使用系统 Windows.Media.Ocr 本地识别并保留换行；成功后自动写入 Unicode 文字。读图及持有剪贴板锁写入时均核对序列号，避免覆盖新复制的内容。没有图片、没有文字、缺少 OCR 语言组件、取消或超时不写剪贴板。`quick.snapshot.output` 保留完整识别结果；成功写回不显示完成提示，`output_notice` 仅在尚未写回时提示，写回失败仍可手动复制。图片与结果临时文件在 finally 中清理，不进入 Job 参数、结果、事件及进程日志；OCR 图片上限 32 MiB / 2500 万像素，按系统最大边长缩小，最长 60 秒，同一上下文重复点击复用运行中的任务。

翻译独立角色为 `quick_translate`，新配置默认阿里云 `qwen3.8-flash`，缺失角色时复用现有 dashscope 提供商；不覆盖已有功能分配。原生 `quick_snapshot`、`quick_hide`、`quick_copy {text}` 管理瞬态窗口及显式复制。选区由短生命周期 STA helper 获取，不模拟复制；长按开始的瞬间即并行预取选区并预建隐藏菜单窗口（与长按时长重叠，取消按压立即终止读取进程）；划词模式在鼠标划选或双击结束后读取一次并静默记住选区（60 秒、单次使用，普通左键单击丢弃），不自动弹窗，跳过非外语、密码框和工具箱自身窗口；打开快捷菜单优先使用现场读取，现场为空时回退到记住的选区并自动翻译；窗口隐藏约 30 秒后销毁。自定义脚本上下文临时文件在 finally 中删除，输出最多读取 16000 字节，60 秒超时。使用与测试见 `docs/QUICK-MENU.md`。

Feishu p2p/group routing: ordinary new messages use the rule target, subject to the pending group-question exception below; replies follow verified same-chat message ancestry and persistent `message_contexts` (app/chat/message → local Codex thread). Unknown sources may be recovered from unique successful bot-send execution receipts in local Codex history. An uncached group bot question uses its own send receipt before any older discussion mapping. Unknown/ambiguous bot replies fail without default fallback. Group replies to bot/context messages can omit a repeated mention; unrelated unmentioned human replies are ignored before acknowledgement. Group rule authorization still applies in the destination chat. Existing jobs gain a nullable `target_thread_id`; no historical target is guessed from mutable rule settings.

Unthreaded group bot mentions first check verified `pending_questions` in the rule's `pending_question_hours` window (default 168; 0 disables). Questions addressed to the current sender take priority, then general questions, then other waiting questions. A unique source chat wins; multiple source chats require an explicit Feishu reply and yield `needs_context` without dispatch or thinking acknowledgement. No waiting question preserves the default. Explicit reply ancestry always wins. State remains open until a subsequent bot answer; persisted answer IDs support completion recovery after restart. History paging is bounded at 1000 messages; incomplete history must not claim no waiting questions.

## 脚本工具

本机脚本的清单化管理：竖向列表，每条一个脚本文件，运行走后台任务并把 stdout/stderr 收进该条目自己的终端面板。脚本内容不进入协议，工具箱只负责列表、启动、输出与停止。

清单保存在本机 `%LOCALAPPDATA%/WinToolbox/script-tools/state.json`（脚本路径是本机事实，不进入同步的应用数据；测试与迁移可用参数 `state_root` 覆盖）。条目字段：`id`、`name`、`note`、`path`、可选 `builtin`/`seeded_sha256`/`update_available`/`last_job_id`。

支持的类型与启动方式：`.py` 用工具箱自带的 Python，`.ps1` 用 pwsh（缺失时 powershell）`-NoProfile -ExecutionPolicy Bypass -File`，`.cmd`/`.bat` 用 `cmd /c`，`.exe` 直接启动，`.js`/`.mjs` 用 PATH 上的 node（缺失时在启动前报错）。工作目录为脚本所在目录，子进程无控制台窗口，取消会终止整棵进程树；单次运行上限 30 分钟。

- `script_tools.list {}` → `entries[]`（含 `exists`、`runner`、`folder`、`openable`、`runnable`、`builtin`、`builtin_asset`、`update_available`、`last_job_id`）与 `scripts_dir`。每次调用都会确保随包提供的内置脚本已就位。
- `script_tools.add {path,name?,note?}` → `entries`、`id`。路径必须是受支持类型的已存在文件，重复加入同一路径被拒绝；名称缺省取文件名，上限 80 字，说明上限 400 字。
- `script_tools.update {id,name?,note?}`、`script_tools.remove {id}` → `entries`。移除只出列表，脚本文件保留，且不会再被自动添加回来。
- `script_tools.reset {id}` → `entries`。仅内置脚本：用当前版本随包的脚本覆盖该文件（用户改动会被覆盖）。
- `script_tools.run {id}` → 后台 Job（`script-tools.run`）。文件不存在或类型不受支持时在排队前报错。任务参数只含条目 id、名称与路径；运行后条目记住 `last_job_id`。
- `script_tools.console {job_id}` → `status`、`progress`、`message`、`error`、`created_at`、`finished_at`、`name`、`path`、`runner` 与 `output`（该任务 `console.log` 的末尾 64 KiB）。运行中可反复调用以显示实时输出。未知任务报错。

随包提供的内置脚本在首次使用时复制到 `script-tools/scripts/` 并记入 `seeded`：未被改动过的副本随工具箱升级自动更新，被改动过的副本永不覆盖，只标记 `update_available`。内置脚本 `dsh-mcp-sync.py` 把 Codex `config.toml` 的 `[mcp_servers]` 写成 DeepSeek Harness 的 `@deepseek-ai/dsh-mcp-client` 插件行，默认目标为 `DSH_HOME/profiles/<DSH_PROFILE 或 desktop>/cordis.patch.yml`，生成内容只位于 `# >>> dsh-mcp-sync` 与 `# <<< dsh-mcp-sync` 之间，写入前备份原文件。它支持 `--dry-run`、`--source`、`--target`、`--exclude`、`--codex-home`、`--dsh-home`、`--profile`，其中的跳过名单是可编辑的文件内容而不是工具选项。

内置脚本 `dsh-skill-sync.py` 让 Harness 直接读取 cc-switch 维护的技能库：在同一份补丁里维护 `# >>> dsh-skill-sync` 与 `# <<< dsh-skill-sync` 之间的一段，插入 `skill-ccswitch` 行（`@deepseek-ai/dsh-skill-filesystem` 的独立提供方，`providerName: cc-switch`、`includeDefaultRoots: false`、`customSkillDirs` 只含技能库目录），因此技能库的增删改名不需要同步或复制。它同时按 `dsh-skill` 的 `SKILL_NAME` 语法与 `description` 是否为空检查库内每个技能，并点名 Harness 会静默跳过的条目，以及标记段外已存在的同名 `skill-ccswitch` 条目（此时拒绝写入并指出行号，避免把同一提供方挂载两次）。参数为 `--dry-run`、`--library`、`--target`、`--dsh-home`、`--agents-home`、`--profile`；库目录默认 `~/.cc-switch/skills` 或环境变量 `DSH_SKILL_LIBRARY`。

账户位于 engine.sqlite3 的 ai_quota_accounts_v1，独立凭据 DPAPI 加密；public account 含 id/provider/name/source_provider_id/status/error/checked_at/snapshot，永不返回 credential/revision。snapshot 含 fetched_at、balances（label/value/currency）、meters（label/unit/used?/total?/remaining?/used_percent/remaining_percent/resets_at?），可选 plan/expires_at/note/spend/available。status 为 not_checked/ok/auth_required/rate_limited/error。失败保留上次成功 snapshot，UI 必须标为上次查询并显示时间，不能将缺失额度补成零。支持范围、平台口径与来源见 [AI-QUOTA.md](AI-QUOTA.md)。

## 硬盘挂载

`netmount.status` 返回 engine（rclone 1.75.2）/winfsp 状态、taken_letters 与 drives（state/mounted/message/restarts）。`netmount.save` 按 RaiDrive 语义处理密码：留空保留旧值（同端点+账户），换端点/账户或 clear_password 清除；挂载中拒绝修改。`netmount.mount` / `netmount.unmount` / `netmount.test` 是后台任务；mount 最多等 30 秒盘符就绪，失败带 rclone 日志末行。挂载即启动监督线程：意外退出且存活超过 10 秒则 5 秒后用已存密码重启（最多 10 次，稳定 300 秒重置），启动即崩报错不重试。`netmount.import_raidrive` 解析 RaiDrive 服务日志恢复名称/类型/地址/盘符/只读（密码不可导出），`netmount.import_raidrive.apply` 批量保存并逐条报告；`netmount.import_webdav_sync` 返回 WebDAV 备份连接候选，表单保存时可 `reuse_webdav_password` 复用其密码。凭据只存当前用户 DPAPI 密文于 data/netmount.json（不在备份白名单）；rclone 子进程用 RCLONE_CONFIG_* 环境变量与 obscure 后的密码，argv、任务参数、事件与日志无明文。挂载随工具箱退出（close/prepare_exit）卸载，auto_mount 条目在启动 2 秒后自动挂载。引擎由 scripts/prepare_netmount.py 固定 rclone 版本与 SHA-256。详见 [NETMOUNT.md](NETMOUNT.md)。

## 0.7.1 同步兼容性

- memory.sync.connect {library_id,mode:'merge'|'remote'} -> 后台任务；先只读暂存远端并校验父版本、附件，再在本机写入门下备份与切换。结果含 recovery_path、warnings、conflicts。merge 改写本机操作的库身份并保留操作/实体 ID 与版本关系；remote 采用远端完整记录。本机工程文件保留，匹配的绑定更新库身份。
- ai_aggregation.conflicts {} -> {items:[{id,parents,versions:[{op_id,local,name,model,deleted,created_at}]}]}，不返回凭据；ai_aggregation.resolve {id,parents,op_id} -> {resolved,recovery_path}，按当前 heads 校验、备份并采用版本，再安排上传。
- webdav.migration.sources {} -> {sources:[{key,url,username,remote_path,error}]}；webdav.migration.save {key,url?,username?,remote_path?,password?} 更新旧位置连接并重试，不替换当前共享连接。密码不进入返回或任务参数。
- 配置备份 v3 扩展见 CONFIG-BACKUP.md；v2 继续可读。新增配置必须登记导出、验证、导入、凭据处理与升级兼容。

- ai_aggregation.use_remote {} -> 后台任务，经统一服务互斥；只读校验远端后备份并替换本机聚合账户/调用配置/同步日志，不解密本机旧凭据。运行中重复覆盖请求明确提示重试，不把覆盖静默合并成普通同步。
