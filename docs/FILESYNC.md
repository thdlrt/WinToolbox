# 文件同步

从工具首页进入「文件同步」，可星标固定到侧栏。文件和文件夹均支持单向、双向同步。所有扫描、导入和复制在后台任务中运行，可取消；编辑或删除运行中的规则会提示等待。

1. 新建规则，填写源与目标的绝对路径。文件规则的目标是完整文件名；目录规则的目标不能包含源目录，也不能与其他规则重叠。
2. 点选规则，点击「预览同步」。检查每项新增、覆盖、删除和冲突，再「确认同步」。执行前重新计算内容指纹；规则或文件变化时要求重新预览。
3. 双向首次遇到不同内容、两侧同时修改、删除与修改同时发生时，需要选择保留哪一侧。选择不存在的一侧代表确认删除另一侧，删除前备份。
4. 确认规则后可开启自动同步。工具箱运行期间按配置间隔（至少 5 秒）轮询并计算 SHA-256。此版统一采用轮询，未保留旧版文件监听；自动同步遇到冲突会保留两侧并记录错误。工具箱退出后停止，托盘常驻和自启动沿用工具箱的设置。

## 数据与备份

规则、每个文件的内容基线和最近记录保存在工具箱 `engine.sqlite3` 的独立表中，随工具箱备份迁移。还原整机工具箱备份后自动暂停全部同步规则，避免另一设备上的旧路径立即开始同步。

覆盖和删除之前，把原内容备份到被修改路径的父目录下 `.back/wintoolbox-filesync/<规则 ID>/<备份 ID>/`。`content` 是原文件，`manifest.json` 记录原路径、SHA-256 和备份创建时间。点击「查看备份」可打开位置，按清单把 `content` 复制回原路径即可手动恢复；旧版 `.back` 备份不迁移、不清理。

保留天数按**备份创建时间**计算，0 为永久。仅清理此规则创建且带有效清单的新版备份，不递归清理用户共享的 `.back`。规则删除只移除规则记录，不删除同步文件或备份。

文件夹过滤按相对路径进行，支持 `*`、`?`、`[]` 和 `**/`，路径分隔符统一为 `/`，匹配忽略大小写。多个模式逐行输入；包含条件为空代表全部文件，排除条件优先。`.git`、`.back` 和同步临时文件始终排除。不复制空目录，不跟随符号链接或目录联接；遇到无法读取的文件会停止本次同步，避免不完整扫描触发删除。

「传播删除」默认关闭。单向开启后会备份并移除目标中符合过滤规则的独有文件；双向只传播已经建立同步基线、且另一侧未再修改的删除。已建立基线的根目录或单文件的父目录不可用时停止，避免把离线目录当作批量删除。这里的同步是按文件执行，不是整个目录的原子事务；中途失败或取消时，已经成功的文件保留，逐文件基线用于继续同步。

## 从旧 FileSync 迁移

「导入旧配置」读取 `com.filesync.notes/store.json`，可自动发现当前 Windows 用户的配置位置。导入后自动同步一律关闭，旧的仅含文件名的同步清单不当作内容基线使用。重复或重叠路径拒绝导入，单条损坏规则不影响其他规则。源文件和旧配置保持不变。

若旧 JSON 损坏，可点击「从日志恢复规则」或选择 `app.log.jsonl`。只提取日志中实际执行过且至少一端仍存在的路径；相同路径改过名称时使用最近名称。日志没有同步方向、过滤条件和删除策略，因此统一恢复为**双向、无删除、手动同步**。请检查路径和预览后按需要调整。

本次发现旧配置的两个历史副本都是全零字节，当前配置仅有空路径占位记录；日志仍可恢复路径。不能从这些损坏文件恢复原过滤条件或方向。

## 已修复的问题

- 同大小、同修改时间但内容不同不再漏同步：始终校验内容哈希。
- 不再以最后修改时间决定双向覆盖方向：根据持久内容基线识别单侧变化和冲突。
- 替换失败不再删除原目标：同目录临时文件写入、刷新和校验后调用原子替换。
- 复制过程中源或目标变化会停止；备份成功并验证后才覆盖或删除。
- 删除与修改冲突、离线目录、过滤排除、链接路径、重叠规则、并发执行、过期预览和中断重试都有单独处理。

测试：`core/.venv/Scripts/python.exe -m pytest tests/test_features_filesync.py -q`。全部测试只使用临时目录，不操作真实笔记。
